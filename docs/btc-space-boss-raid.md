# BTC 스페이스 보스 레이드 개발 계획서

> 버전: v0.5
> 기준일: 2026-11-13
> 상태: **§7 의 1 ~ 4단계 구현.** 남은 것은 5단계(탭 여러 개 동시 접속, 모바일 프레임 측정, 수치 조정)와 보스 몸통 충돌(§5.2)이다
> 선행 문서: [`btc-space-3d.md`](./btc-space-3d.md) §11 (위치 동기화·공격 동작)
> 1차 범위: 안뜰에 보스 1마리, 2시간 주기 젠, 유저 체력, 사망·리스폰, 전투 UI
> 범위 밖: 인원수 보정, 보상(라이트닝), 아이템·장비 (§10)

안뜰(눈 내린 외부 맵)에 보스 몬스터가 주기적으로 나타나고, 여러 유저가 함께 잡는 콘텐츠다. 이 문서는 **무엇을 어떤 순서로 만들지**와 그 전에 정해야 할 것만 적는다. 좌표 1 유닛은 1 m, 시간은 초(s)다. 수치는 전부 초기값이고 개발하면서 조정한다.

## 1. 확정된 결정

| 항목 | 결정 |
| --- | --- |
| 판정 주체 | **전부 서버.** 보스 체력·위치·타깃·패턴, 유저 체력, 피격 판정을 `SpaceRoom` 이 가진다 |
| 보스 활동 범위 | 안뜰의 평평한 바닥 안. 서버가 지형을 모르므로 계단·홀로는 못 나간다 |
| 보스 공격 방식 | 바닥 예고 표시 뒤 정해진 시각에 판정. 즉발 공격은 없다 |
| 어그로 | 아레나 안 누적 피해 1위를 쫓는다. 아직 아무도 안 때렸으면 먼저 들어온 사람을 쫓는다 |
| 리셋 | 아레나에 대상이 없으면 제자리로 돌아가 체력을 회복한다 |
| 유저 사망 | 홀 안으로 리스폰한다 |
| 유저 회복 | 홀 안에 있으면 체력이 자동으로 찬다 |
| 젠 주기 | 2시간 단위 벽시계 기준. 못 잡으면 계속 남고, 살아 있으면 다음 젠 시각에도 그대로 유지한다 |
| 인원수 보정 | 넣지 않는다 |
| 보상 | 막타 유저에게 라이트닝 보상. **게임 완성 뒤 별도 작업** |
| 중간 입장 | 입장 응답에 보스 현재 상태를 싣는다 |
| 숨은 탭 | 그대로 맞는다. 10초간 입력이 없으면 어그로 후보에서 뺀다 |

## 2. 지금 있는 것

착수 전에 코드와 에셋에서 확인한 사실이다.

### 2.1 보스 에셋 — `public/models/bear-raid-boss.glb`

원본은 `assets/Bear-Raid-Boss.glb` 이고 같은 파일을 복사했다. Draco 압축은 안 했다(용량 대부분이 모션 키라 효과가 작다).

| 항목 | 값 |
| --- | --- |
| 크기 | 559 KB, 삼각형 약 3,000개, 관절 16개, 텍스처 없음(머티리얼 색) |
| 키 | 4.5 m (아바타의 약 2.5배) |
| 정면 | glTF +Z |
| 공격 모션 | `Swipe` 2.21 s, `Slam` 2.71 s, `Charge` 2.96 s |
| 그 밖의 모션 | `Idle` 2.5 s · `Walk` 1.25 s · `Run` 0.67 s (반복), `Turn` 0.67 s, `Hit` 0.42 s, `Stagger` 1.75 s, `Enrage` 1.75 s, `Spawn` 2.0 s, `Death` 2.5 s |

공격 범위와 타이밍이 `Bear_Rig` 노드의 `extras.attackRanges` 에 들어 있다. 서버 판정은 이 값을 그대로 옮겨 쓴다.

| 공격 | 모양 | 크기 | 예고 완료 | 판정 시각 | 비고 |
| --- | --- | --- | --- | --- | --- |
| Swipe | 부채꼴 | 반지름 3.5 m, 120° | 0.67 s | 0.96 s | 보스 발밑 기준 |
| Slam | 원 | 반지름 4 m | 0.96 s | 1.38 s | 중심이 보스 앞 2.3 m |
| Charge | 직선 | 폭 3 m, 길이 9 m | 0.83 s | 1.0 ~ 1.92 s | **보스가 9 m 전진한다**(루트 모션) |

**에셋에서 고칠 것:** `Turn` 의 0.33 → 0.38초에 왼팔뚝(`forearm.L`)이 한 프레임에 114° 튄다. 오른팔뚝은 같은 클립에서 프레임당 20° 안팎이다.

모션 길이·판정 시각·보폭 속도·돌진 이동표는 `src/entities/space/model/boss.ts` 에 옮겨 두었고, `boss.test.ts` 가 GLB 를 직접 열어 맞는지 고정한다. 에셋을 다시 구우면 그 테스트가 먼저 깨진다.

### 2.2 서버 — `workers/chat/src/SpaceRoom.ts`

- **상시 틱이 없다.** 100 ms 스냅샷 틱은 누가 움직일 때만 돌고, 마지막 이동 뒤 빈 틱 2번을 보내면 멈춘다.
- **알람은 시세 감시가 쓰고 있다.** Durable Object 의 알람은 하나뿐이고 `spaceMarketMonitor` 가 쓴다. 보스 젠을 알람에 걸면 서로 덮어쓴다.
- **유저 상태는 소켓 attachment 에 있다.** 좌석·위치·마지막 공격 시각이 들어 있고 hibernation 에서 살아남는다.
- **공격 프레임이 이미 있다.** `kick` 프레임은 서버가 쿨다운(1초)을 검증하고 모두에게 동작을 중계한다. 유저끼리의 판정은 v0.59 에서 뺐다 — 보스용으로 비워 둔 자리다(`kick.ts` 주석).
- **서버는 유저를 강제로 옮긴 적이 없다.** 위치는 항상 클라이언트가 보내고 서버는 검증만 한다. 리스폰은 서버가 위치를 정하는 첫 사례다.
- **모르는 프레임은 무시된다.** 클라이언트 파서가 알 수 없는 `t` 를 `ignored` 로 돌려주므로, 프레임 종류를 추가해도 프로토콜 버전을 올릴 필요가 없다. 버전을 올리면 캐시된 구버전 PWA 가 끊긴다.

### 2.3 맵

- 안뜰은 홀 +X 벽 너머(x 21…51)이고 바닥 높이는 GLB y = 2 다. 맵 GLB 에 `Snow_Arena_Center` 노드(38, 2, −1)가 있다.
- **맵을 수정 중이다.** 아레나 범위와 리스폰 좌표는 수정본이 나온 뒤에 확정한다. 서버 쪽 작업(§7 의 1·2단계)은 맵과 무관하게 먼저 할 수 있다.

## 3. 서버 설계

### 3.1 파일 구성

| 파일 | 내용 |
| --- | --- |
| `src/entities/space/model/boss.ts` | 서버·클라이언트가 같이 쓰는 상수. 체력, 공격 범위·타이밍, 아레나, 젠 주기 (`kick.ts` 와 같은 자리) |
| `src/entities/space/lib/bossSchedule.ts` | 젠 시각 계산. 순수 함수 |
| `src/entities/space/lib/bossHitTest.ts` | 부채꼴·원·직선 판정. 순수 함수 |
| `src/entities/space/lib/bossSimulation.ts` | 보스 상태머신. 시계와 유저 목록을 주입받는 순수 로직. 워커 폴더가 아니라 여기 둔 것은 개발용 미리보기도 같은 두뇌를 쓰기 때문이다 |
| `workers/chat/src/SpaceRoom.ts` | 틱 연결, 프레임 송수신, 유저 체력 |

### 3.2 젠 스케줄 — 서버 타이머 없이

2시간 칸을 벽시계에 맞춘다(§9 열린 질문 3: 몇 시 기준인지).

```
현재 칸 시작 = floor(지금 / 2시간) × 2시간
보스가 있다 = 마지막 처치 시각 < 현재 칸 시작
```

- 저장하는 값은 **마지막 처치 시각 하나**다(DO storage).
- 못 잡으면 처치 시각이 안 바뀌므로 계속 "있다"다. 살아 있는 채 다음 칸이 와도 식이 그대로 참이라 유지된다.
- 클라이언트도 같은 식을 쓴다. 입장 응답으로 마지막 처치 시각을 받으면 다음 젠까지 남은 시간을 스스로 계산하고, 젠 시각이 되면 **서버 메시지 없이** 보스를 그린다. 대기 중인 보스는 항상 "아레나 중심, 체력 가득" 이라 서버가 알려 줄 것이 없다.
- 그래서 방이 비어 서버가 잠들어 있어도 되고, 젠 때문에 서버를 깨워 둘 필요도 없다.

### 3.3 보스 상태머신

```
없음 ──(젠 시각)──▶ 대기 ──(아레나에 유저 진입)──▶ 추적
                     ▲                              │ ▲
                     │                     (사거리) ▼ │ (후딜 끝)
                  복귀·회복 ◀──(대상 없음)──      공격
                                                     │
                                        (체력 0) ──▶ 사망 ──▶ 없음
```

| 상태 | 동작 |
| --- | --- |
| 없음 | 보스가 없다. 다음 젠 시각을 기다린다 |
| 대기 | 아레나 중심에 서 있다. 체력 가득. **서버 틱이 돌지 않는다** |
| 추적 | 타깃을 향해 걷는다. 타깃은 1초마다 다시 고른다 |
| 공격 | 예고 → 판정 → 후딜. 도중에 방향·위치를 바꾸지 않는다(Charge 의 전진 제외) |
| 복귀·회복 | 아레나에 유효한 대상이 없으면 중심으로 걸어가며 체력을 채운다. 도착하면 대기 |
| 사망 | 처치 시각을 저장하고 모두에게 알린 뒤 없음으로 간다 |

**틱:** 기존 100 ms 스냅샷 틱을 그대로 쓴다. 보스가 대기·없음이 아닐 때는 유저 이동이 없어도 틱을 계속 돌린다. 전투가 끝나면 원래대로 멈춘다 — 서버가 깨어 있는 시간은 전투 중뿐이다.

**공격 선택:** 거리로 고른다. 위에서부터 먼저 맞는 것을 쓴다. 타깃을 0.3 rad 안으로 마주 봐야 시작하고, 공격 사이에 1.5초 쉰다.

| 조건 | 공격 |
| --- | --- |
| 내려찍기 원 안에 유저가 2명 이상 | Slam |
| 타깃이 3.3 m 안 | Swipe 와 Slam 을 번갈아 |
| 타깃이 5.8 m 안 | Slam |
| 타깃이 6 ~ 11 m 이고 전진 끝점이 아레나 안, 직전 돌진에서 6초 지남 | Charge |
| 그 외 | 계속 추적 |

혼자 싸울 때도 내려찍기가 나오게 가까운 거리에서 번갈아 쓰도록 했다. 원안(2명 이상일 때만)대로면 혼자서는 휘두르기만 본다.

**체력 구간 반응:** 체력이 절반 아래로 처음 내려가면 `Enrage`, 1/4 아래로 처음 내려가면 `Stagger` 를 한 번씩 튼다. 하던 공격은 끝내고 튼다. 수치 변화는 없는 연출이다.

**어그로 대상 조건:** 아레나 안에 있고, 살아 있고, 최근 10초 안에 이동이나 공격 입력이 있었던 유저.

**서버 재시작:** 전투 중 상태(현재 체력·누적 피해)는 메모리에만 둔다. 배포 등으로 서버가 다시 뜨면 보스는 체력 가득인 대기 상태로 돌아간다. 처치 여부만 저장되므로 젠 주기는 어긋나지 않는다.

### 3.4 유저 → 보스 피격

- 새 프레임을 만들지 않고 **기존 `kick` 프레임에 판정을 붙인다.** 쿨다운 검증과 동작 중계가 이미 있다.
- 서버가 보는 조건: 유저가 살아 있음, 보스까지 거리가 사거리 안, 유저가 보스 쪽을 보고 있음.
- 거리는 보스 몸통 반지름을 뺀 값으로 잰다. 보스가 커서 중심 기준이면 닿지 않는다.
- 맞으면 고정 피해를 주고 유저별 누적 피해에 더한다.

### 3.5 보스 → 유저 피격

- 공격을 시작할 때 종류·위치·방향·시작 시각을 모두에게 보낸다. 클라이언트는 그 시각부터 모션과 예고 표시를 재생한다.
- 판정 시각이 되면 서버가 **그 순간 서버가 알고 있는 유저 위치**로 범위 안을 계산한다.
- 서버가 아는 위치는 실제보다 0.1 ~ 0.3초 늦다. 유저에게 유리하도록 판정 범위를 예고 표시보다 조금(약 0.3 m) 작게 잡는다.
- Charge 는 전진하는 동안 틱마다 몸통 범위를 판정하되, 한 번의 돌진에 같은 유저는 한 번만 맞는다.

### 3.6 유저 체력·사망·리스폰

| 항목 | 초기값 |
| --- | --- |
| 최대 체력 | 100 |
| 홀 안 회복 | 초당 10 |
| 안뜰에서 회복 | 없음 |

- 체력은 소켓 attachment 에 둔다.
- **재접속으로 체력을 채우지 못하게** 전투 중에는 유저 식별키(`stableActorKey`)별 체력을 메모리에 따로 기억해 재입장 때 돌려준다.
- 체력이 0 이 되면 서버가 위치를 홀 안 스폰 고리(기존 `createSpawnPoint`)로 바꾸고 본인에게 리스폰 프레임을 보낸다. 클라이언트는 그 좌표로 순간이동한다.
- 리스폰 직후 서버가 이동 검증의 기준 위치도 같이 옮겨야 한다. 안 그러면 다음 이동이 "한 번에 너무 멀리 갔다" 로 반려된다.
- 리스폰 때 체력을 가득 채울지, 0 에서 홀 회복으로 채울지는 §9 열린 질문 4.

### 3.7 악용 방지

- 공격 빈도는 기존 `kick` 쿨다운이 막는다.
- 사거리·방향은 서버가 본다. 홀 안에서는 거리가 안 닿아 때릴 수 없다.
- 죽은 유저의 공격은 버린다.
- 좌표 조작으로 범위 밖에 서 있는 것은 막지 못한다. 서버가 지형을 모르는 기존 한계와 같은 선에서 받아들인다.

## 4. 프로토콜

스냅샷 바이너리 포맷과 `SPACE_PROTOCOL_VERSION` 은 **건드리지 않는다.** JSON 프레임만 추가하고, 기능 플래그 `boss-v1` 을 알린 클라이언트에게만 보낸다(`kick` 과 같은 방식).

| 프레임 | 방향 | 시점 | 내용 |
| --- | --- | --- | --- |
| `welcome` (확장) | 서버 → 본인 | 입장 | 마지막 처치 시각, 전투 중이면 보스 상태 전체, 내 체력 |
| `boss` | 서버 → 전체 | 전투 중 매 틱, 쉬러 들어갈 때 한 번 더 | 상태·공격 종류·**시작 서버 시각**·위치·방향·공격 시작 자리·체력·타깃 좌석 |
| `boss-hit` | 서버 → 전체 | 유저가 보스를 맞힘 | 때린 좌석·피해량·남은 체력 (피해 숫자 표시용) |
| `hp` | 서버 → 본인 | 보스에게 맞음 | 현재 체력, 맞은 공격 종류 |
| `respawn` | 서버 → 본인 | 사망 | 리스폰 좌표, 다시 움직일 수 있는 시각 |
| `boss-dead` | 서버 → 전체 | 처치 | 처치 시각, 막타 좌석, 피해 순위 상위 5 |

- `boss-attack` 은 따로 두지 않았다. `boss` 가 매 틱 상태와 시작 시각을 같이 실어서 공격 시작도 그 안에 들어 있다.
- 사망하면 서버가 위치를 홀 스폰 고리로 옮기고 기존 `peer` 프레임도 모두에게 보낸다. 다른 사람 화면의 순간이동은 이것으로 된다.
- 홀 안 회복은 프레임을 보내지 않는다. 서버는 이동이 올 때 지난 시간만큼 정산하고, 클라이언트는 같은 식(홀 안 초당 10)으로 스스로 채워 그린다.
- **보스를 모르는 클라이언트는 보스가 상대하지 않는다.** 쫓지도 때리지도 않고, 그쪽 공격도 보스에 안 들어간다. 안 보이는 공격에 맞아 홀로 튕기는 일을 막는다.

- 전투 중 `boss` 프레임은 초당 10개다. 50명에게 보내도 기존 유저 스냅샷보다 작다.
- 공격은 "지금 몇 초째" 가 아니라 **서버 시각 기준 시작 시각**으로 보낸다. 중간에 들어온 사람도 예고 표시를 이어서 본다. 서버 시각 동기화는 기존 `clock` 프레임을 쓴다.
- 다른 유저의 체력은 1차에서 보내지 않는다(§9 열린 질문 5).

## 5. 클라이언트 설계

### 5.1 보스 렌더

- 아바타는 구운 프레임과 `InstancedMesh` 로 그리지만, 보스는 한 마리라 **스킨 메시와 `AnimationMixer` 를 그대로 쓴다.**
- 위치는 `boss` 프레임을 받아 보간한다. 기존 원격 아바타 보간(`remoteInterpolation.ts`)과 같은 방식이다.
- 공격 모션과 예고 표시는 `boss-attack` 의 시작 시각에 맞춰 클립을 재생하면 같이 나온다. 예고 메시가 클립 안에 들어 있다.
- Charge 는 클립에 전진이 들어 있다. 서버 위치와 이중으로 움직이지 않게 클립의 루트 이동을 빼고 서버 위치만 따른다.
- 대기 상태의 보스는 서버 메시지 없이 젠 계산식만으로 그린다(§3.2).

### 5.2 유저 쪽 처리

- 보스 몸통을 통과하지 못하게 기존 아바타 겹침 방지(`separation.ts`)에 보스를 큰 반지름으로 넣는다. 클라이언트 처리만으로 충분하다.
- `respawn` 을 받으면 로컬 위치를 덮어쓴다. 탭이 숨어 있다 돌아온 경우에도 같은 경로다.
- 맞았을 때 화면 가장자리 붉은 번쩍임 정도의 피드백을 준다. 넉백은 넣지 않는다 — 넉백 예측이 지연에서 꼬였던 문제를 다시 만들지 않는다.

### 5.3 UI

| 요소 | 위치 | 표시 조건 |
| --- | --- | --- |
| 보스 체력바 + 이름 | 화면 위 가운데 | 전투 중이거나 내가 아레나 안 |
| 내 체력바 | 조작 버튼 근처 | 체력이 가득이 아니거나 아레나 안 |
| 피해 숫자 | 보스 머리 위에 떠오름 | 누가 보스를 맞힐 때. 내 피해는 강조 |
| 사망 화면 | 전체 화면 덮개 | 사망 ~ 리스폰 |
| 다음 젠 타이머 | 안뜰 입구 또는 HUD | 보스가 없을 때 |
| 처치 결과 | 가운데 잠깐 | 처치 직후. 막타·피해 순위 |

**구현:** `SpaceBossHud.tsx`(HUD)와 `BossDamageNumbers.tsx`(씬). 무엇을 띄울지는 순수 함수 `bossHud.ts` 가 정하고, `useBossHud` 가 0.2초마다 읽어 값이 달라졌을 때만 다시 그린다.

- 보스 체력바는 안뜰에 있거나 보스가 다쳐 있을 때 뜬다. 싸움을 걸고 홀로 피해 있어도 보인다.
- 내 체력바는 다쳤거나, 보스가 있는 안뜰에 나와 있을 때 뜬다. 홀 안 회복은 서버가 안 알려 줘서 같은 식(초당 10)으로 채워 그린다.
- 피해 숫자는 맞은 순간의 보스 자리에 박아 두고 동시에 10개까지만 띄운다. 내 피해는 주황색으로 크게 나온다.
- 사망 화면은 리스폰까지 남은 초를 센다. 우측 상단 버튼(뒤로 가기 등)은 그 위에 있어 계속 눌린다.
- 젠 타이머는 보스가 없을 때 안뜰에 있으면 화면 위 가운데에 뜬다.
- 처치 결과는 9초 동안 가운데에 뜬다.

모양은 카드가 아니라 HUD 의 다른 패널(인원 배지, 조작 안내)과 같은 반투명 검정 판을 썼다. 3D 화면 위에 뜨는 것이라 `card-surface` 의 옅은 흰 바탕은 글자가 안 읽힌다.

### 5.4 성능

- 보스 한 마리는 삼각형 3,000개, 텍스처 없음이라 부담이 작다.
- 피해 숫자는 동시에 뜨는 개수에 상한을 둔다. 50명이 초당 1번씩 때리면 초당 50개다.
- 모바일에서 실제 프레임을 재서 확인한다.

### 5.5 모션 연결 — 구현됨

`bossModel.ts`(에셋 손보기) · `bossAnimator.ts`(재생) · `RaidBoss.tsx`(씬) 에 들어 있다. 입력은 `SpaceBossState` 하나이고, 서버가 붙으면 `boss` · `boss-attack` 프레임을 이 모양으로 옮겨 넣으면 된다.

| 항목 | 결정 | 이유 |
| --- | --- | --- |
| 이동 | 추적은 `Run` 4 m/s, 복귀는 `Walk` 1.25 m/s. 재생 속도를 실제 속도 ÷ 보폭 속도로 맞춘다 | `Walk` 를 4 m/s 로 틀면 발이 3배 넘게 미끄러진다 |
| 제자리 회전 | 서 있다가 70° 넘게 돌아야 하면 `Turn` 을 틀고 0.125 ~ 0.54초 사이에만 방향을 옮긴다. 달리는 중에는 초당 160° 상한으로 곡선을 그린다 | 에셋의 발 디딤 구간과 맞춤 |
| 예고 표시 | `AOE_*` 노드를 보스 몸과 분리한 묶음으로 옮겨 **공격 시작 자리에 고정**한다 | 원본은 씬 최상위에 있어 보스를 옮기면 예고도 끌려간다 |
| 돌진 | 모션에서 루트 전진을 빼고 위치는 `resolveBossChargeTravel` 이 준다. 서버도 같은 함수를 쓴다 | 등속이 아니다(최고 12 m/s). 직선 근사는 중간에서 0.75 m 어긋난다 |
| 피격 | `Hit` 을 전신으로 틀지 않고 지금 모션 위에 얹는다(가산, 세기 0.75, 최소 간격 220 ms) | 여러 명이 초당 한 번씩 때려서 전신으로 틀면 공격 모션이 매번 끊긴다 |
| 등장 | 웅크린 첫 프레임으로 0.9초 동안 눈밭에서 솟아오른 뒤 `Spawn` 모션으로 일어선다. 무적은 0.9 + 1.25초 | 에셋 모션에 나타나는 동작이 없다 |
| 처치 | `Death` 로 뒤로 넘어져 1.6초 누워 있다가 1.8초 동안 가라앉는다 | 에셋 모션에 사라지는 동작이 없다 |

**미리보기:** 개발 환경에서 `/space?boss=1` 로 들어가 안뜰로 가면 서버 보스 대신 내 화면에서만 도는 흉내 보스(`bossPreview.ts`)가 나온다. 쫓고 · 공격하고 · 맞고(20대에 처치) · 다시 나온다. 유저는 맞지 않는다. 두뇌는 서버와 같은 `bossSimulation.ts` 라서, 워커 없이(`?dummies=N` 포함) 모션과 패턴을 볼 때 쓴다.

### 5.6 서버 보스 받기 — 구현됨

`features/space-session` 의 `bossTracker.ts` 가 서버 정보를 그릴 상태(`SpaceBossState`)로 바꾸고, 씬이 매 프레임 `session.sampleBoss(now)` 로 갱신한다.

| 상황 | 그리는 방법 |
| --- | --- |
| 쉬는 중 | 서버 프레임이 없다. 입장 때 받은 마지막 처치 시각과 젠 계산식으로 가운데에 세우고, 젠 직후면 솟아오르는 중간부터 튼다 |
| 싸우는 중 | `boss` 프레임(10 Hz)의 위치·방향을 부드럽게 따라간다. 3 m 넘게 벌어지면 바로 옮긴다 |
| 돌진 | 서버 틱을 기다리지 않고 이동표로 위치를 구한다. 예고 띠와 같은 식이라 어긋나지 않는다 |
| 피격 | `boss-hit` 을 받은 순간 움찔한다 |
| 싸움 끝 | 서버가 쉬러 들어가며 보낸 마지막 프레임을 받으면 젠 계산으로 돌아간다. 프레임이 2초 넘게 끊겨도 같다 |
| 내가 쓰러짐 | `respawn` 으로 다시 움직일 수 있는 시각을 받고, 뒤따르는 `peer` 로 자리가 옮겨진다. 그때까지 이동·공격 입력을 막는다 |

서버가 보스를 모르면(입장 응답에 보스 정보가 없으면) 보스를 그리지 않는다. 시계 왕복 전에는 입장 응답에 실린 서버 시각으로 어림해 그린다.

## 7. 작업 순서

| 단계 | 내용 | 끝났다고 보는 기준 |
| --- | --- | --- |
| 1 | 공용 상수, 젠 계산, 범위 판정 함수 | 단위 테스트 통과 |
| 2 | 서버 상태머신, 유저 체력, 피격 판정, 프레임 송신 | 가짜 시계로 젠·추적·공격·복귀·처치·리스폰을 테스트로 재현 |
| 3 | 보스 에셋을 `public/models` 로 옮기고 렌더·보간·모션 연결 | 로컬에서 보스가 보이고 공격 예고가 시각에 맞게 뜸 |
| 4 | 체력바·피해 숫자·사망 화면·젠 타이머 | 한 판을 처음부터 끝까지 진행 가능 |
| 5 | 탭 2 ~ 3개로 동시 접속 검증, 모바일 프레임 측정, 수치 조정 | 중간 입장·숨은 탭·재접속 시나리오 확인 |

- 1 ~ 2단계는 맵 수정과 무관하다. 3단계부터 수정된 맵의 아레나 좌표가 필요하다.
- 서버와 클라이언트를 따로 배포한다. 서버를 먼저 올려도 구버전 클라이언트는 보스 프레임을 받지 않으므로 깨지지 않는다.

## 8. 테스트

- **순수 함수:** 젠 계산(칸 경계, 처치 직후, 한 번도 안 잡은 초기 상태), 범위 판정(부채꼴 경계각, 원 중심 오프셋, 직선 폭).
- **상태머신:** 시계를 주입해 틱을 수동으로 돌린다. 타깃 전환, 대상이 없을 때 복귀, 복귀 중 재진입, 공격 도중 타깃 사망.
- **`SpaceRoom`:** 기존 `SpaceRoom.test.ts` 방식으로 소켓을 흉내 낸다. 쿨다운 안의 공격 무시, 사거리 밖 공격 무시, 사망 뒤 리스폰 좌표와 이동 검증, 재접속 체력 유지, 플래그 없는 클라이언트에게 보스 프레임 미전송.
- **수동:** 탭 여러 개, 탭 숨김, 전투 중 새로고침, 모바일.

## 10. 나중에 할 것

- **보상:** 막타 유저에게 라이트닝 지급. 유저 식별과 지급 경로가 필요하다. 1차에서는 `boss-dead` 프레임에 막타 좌석과 피해 순위를 실어 두기만 한다 — 보상을 붙일 때 프로토콜을 다시 바꾸지 않기 위해서다.
- **아이템·장비:** 유저 공격력·체력을 상수가 아니라 유저별 값으로 읽도록 서버 쪽 접근 지점을 한 곳으로 모아 둔다.
- **인원수 보정:** 체력을 참가 인원에 따라 조정.
- **사운드:** 등장·피격·처치 효과음, 전투 BGM 전환.
- **패턴 추가:** 체력 구간별 패턴 변화.
